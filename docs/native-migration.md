# Native Wiz API controllers

This provider is replacing its Upjet (Terraform) controllers with native ones that call the Wiz
GraphQL API directly. The Terraform provider it wraps (`jschoombee/wiz`) misses much of Wiz's
newer functionality, and the official `wizsec/wiz` provider is not open source.

## How it works

| Piece | Where |
| --- | --- |
| Partial Wiz GraphQL schema (hand-written) | `internal/clients/wizapi/schema/wiz.graphql` |
| Operations the provider sends | `internal/clients/wizapi/operations/*.graphql` |
| Typed client, generated by genqlient | `internal/clients/wizapi/generated.go` (`go generate ./internal/clients/wizapi`) |
| Auth, retry, rate limit | `internal/clients/wizapi/client.go` |
| Shared parameter types | `apis/common/<kind>` |
| Cluster and namespaced API types | `apis/{cluster,namespaced}/<group>/v1alpha1/<kind>_types.go` |
| Controllers | `internal/controller/native/<kind>` |

Native and Upjet controllers run in the same binary and use the same `ProviderConfig` and
credentials secret (`wiz_url`, `wiz_auth_client_id`, `wiz_auth_client_secret`, optional
`wiz_auth_url`, `wiz_auth_audience`, `http_client_retry_max`). The native client uses the standard
`HTTPS_PROXY` environment variable; it does not read the `proxy`, `proxy_server` or `ca_chain` keys.

## The schema is partial

Wiz's API reference is behind a login, so the schema is reconstructed from the public Terraform
provider source and only covers the operations used here. When an introspected schema is available
(`scripts/wiz_introspect.py` in the project files), replace `schema/wiz.graphql` with it and
regenerate; the operations should keep compiling. Anything marked `needs real schema/docs` in the
code was inferred and should be checked then.

## Moving a kind

1. Add its Terraform resource to `nativeResources` in `config/resources.go` and remove it from
   `resourceGroupKinds`, `resourceReferences` and `ExternalNameConfigs`. References from Upjet kinds
   then point at the native Go type.
2. Add its operations to the schema and an `operations/*.graphql` file, then `go generate`.
3. Write shared types in `apis/common/<kind>`, the two scoped types, and a controller under
   `internal/controller/native` (the wiring is shared in `native/base`), then register them in
   `internal/controller/native/setup.go`. A kind in a new API group also needs its group registered
   in `apis/*/register_native.go`; one in a group Upjet still generates (like `iam`) shares that
   group's generated `SchemeBuilder`. References to other kinds are resolved by a hand-written
   `ResolveReferences`, because the referencing field lives in the shared parameters.
4. Run `make generate` and remove the kind's old examples and docs.

Keep the group, kind and external name (the Wiz ID) the same where you can, so existing objects keep
pointing at the same Wiz object.

## Status

| Kind | Controller | Notes |
| --- | --- | --- |
| Project | native | Wiz cannot delete projects, so deleting a Project archives it. The old `CloudAccountLink` kind is now `spec.forProvider.cloudAccountLinks`. |
| User | native | `assignedProjectIds` left unset is not managed; `[]` removes every assignment. `isSuspended` is new. Role and projects are read from Wiz's effective values, which a SAML group mapping can override. |
| ServiceAccount | native | Wiz cannot update a service account: `name`, `type` and `scopes` are immutable, and a change to `assignedProjects` reports a sync error until the resource is recreated. The connection secret gets `client_id` and `client_secret` on create only. `recreateIfRotated` is gone; `status.atProvider.lastRotatedAt` shows a rotation done outside Crossplane. |
| All other kinds | Upjet | Unchanged. |
